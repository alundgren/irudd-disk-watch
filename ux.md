# Disk Watch interface

Space answers which folders use the disk and how recently their contents were written. Changes compares captured sizes; Settings manages tracked data and exclusions.

Space filters sit under the Name and Age column headings: a "Name contains" box and "older than N days". Typing waits a moment before searching. Any filter replaces the tree with a flat list of the largest matching items in the selected scan, each labeled with its full path and expandable into its normal contents. A matching folder hides matches inside it, so no item is counted twice. Name matching is a plain substring that ignores ASCII case; `%` and `_` match themselves. Age uses the latest captured write, so a folder matches only when nothing inside it changed within that time, and items without a write time never match. Hidden paths stay out of the list and out of folder sizes. Files grouped as smaller files have no name to match, and the status line says so. When more than 1,000 items match, the line reads "Showing the largest 1,000 of N matches". Clear restores the tree.

The filtered list supports selecting many items at once. Click selects one row, Shift-click selects a range, Cmd-click on macOS and Ctrl-click elsewhere toggles a row, and dragging from a row draws a rectangle that selects the rows it touches. The drag starts after a few pixels of movement, so ordinary clicks still work. Cmd/Ctrl+A selects every listed match, Escape clears, Space toggles the focused row, Shift+arrow keys extend the range and Enter or the chevron opens a folder. The status line shows "N selected · size" with Queue for deletion… and Clear selection. Queue for deletion… opens a confirm dialog with the count, estimated size, the first ten paths and every skipped item with its reason: already queued, inside a queued folder, root or top-level item, deletion unavailable for the root, the 1,000-item queue limit or a refusal from staging such as unreadable items inside. Queued items inside a selected folder merge into it. Bulk queueing only adds; it never removes queued items. The dialog reminds that a fresh scan is needed after deleting before more items can be queued. The single-row context menu works as before.

Treemap answers which folders occupy the most space visually. Rectangle areas represent visible logical bytes from the selected scan. Muted colors distinguish sibling folders, and nested children inherit their parent's color. Colors do not imply a file category. Click a folder to zoom in and use the breadcrumb path to return. Right-click and keyboard context menus reuse the file actions from Space. Stripes identify captured smaller-file totals, which cannot be acted on individually. Large folders group their smallest entries into an expandable other-items tile. Only the largest readable folders preview children, keeping large scans responsive.

The approved Scope mockup is `disk-watch-folder-activity`, revision 5. Its desktop layout gives Name the largest share, while the other columns expand with the window. Writer attribution is unavailable, so Space redistributes that column's space to Name, Size, Files and Age at 38%, 22%, 16% and 24%.

Names and sizes lead through weight. Counts stay quiet. Latest write and creation share one line with pencil and circled-plus symbols; creation keeps the smaller muted type. Edits less than a day old use sage. Missing values leave blank space. Hover text explains the symbols without permanent legend labels.

Child indentation and a shared background tint express hierarchy. The Age column shares its row's background. Floating menus use a shadow to separate them from the table. Secondary row actions live in the context menu, available by right-click, Menu or Shift+F10.

The app uses the existing warm-paper palette and system UI fonts for offline operation. No theme or web-font request is needed.

Deletion failures open a large modal for investigating the blocked path. The queued path and exact failed operation stay separate because a child or containing folder can cause the failure. The modal lists every failed queued target and the available process values in labeled rows. Values wrap and stay selectable, with Copy beside each available value and Copy report in the fixed footer. Details scroll while the title and Close action stay visible. View details reopens the same snapshot after Close. Process lookup labels distinguish file users from open handles and say when Windows cannot identify an owner. The app leaves process stopping to the user and keeps the existing queue for retry.

Tracked roots show their machine alongside the path. SSH setup asks for an existing SSH destination and remote root, then the worker resolves and records the root. Remote file actions copy the displayed path instead of opening a local file browser. Saved history stays browseable without connecting to its machine. Capacity is labeled as a saved observation, with its observation time in Settings and hover details.

Unix node actions retain encoded native components independently of escaped display labels. Hide offers containing folders from the selected node without converting its label back into an operational path. Editing text discards that selection so the worker resolves the new typed path. Remote exclusions use typed remote paths, while row context actions keep the node identity.

Partial scans remain browseable in Space and Treemap, with partial coverage marked in the scan picker and history. Changes offers only scans with complete coverage. Windows elevation guidance appears only for local Windows scans, and NTFS metadata controls appear only for Windows roots.

Unix cleanup starts disabled. Settings explains the owner-controlled, writable, quiescent-tree requirement and enables native validation for that root. Uncertain deletion receipts stay visible with Check deletion status. The app never replays a deletion from that control. A fresh scan after an uncertain operation permits deliberate restaging, even when that scan is partial. A partial scan can stage only items with nothing unreadable at or under them; the refusal names the unreadable count, or asks for an updated worker when the scan does not record where errors happened. The staged summary says freed space may differ when an item came from a partial scan. Windows deletion diagnostics retain their process lookup details; Unix failures name their native error domain and say when process lookup is unavailable.

Tracking starts in an in-app drive chooser for both this computer and SSH machines. A drive row shows its actual path, filesystem, free/total capacity and read-only state. The recommended macOS Data volume leads with "Apps and your files". System and auxiliary volumes stay available behind Show system volumes; the macOS system root explains that it does not include Data. Read-only drives remain selectable for scanning. A separate typed-folder flow performs intentional native inspection, including Windows drive rows whose identity could not be established. Refresh and cancellation preserve tracked roots and saved history; selecting a root does not start a scan.

Space and Treemap offer details for the selected saved scan without a live connection. Partial coverage stays visible, and a zero-byte partial observation explains that it does not establish an empty drive. Details retain the total read-error count, the saved bounded issue sample, any scan message and the scan scope's intentional skip counts. Read errors refer to items, since files as well as folders can fail. Diagnostic replies belong to the selected scan and are discarded after that view closes.

Settings for a local Mac root offers Full Disk Access guidance and a button to open the system settings. The user adds Disk Watch from Applications and enables its switch, followed by an app restart and a fresh scan. SSH and other operating systems do not show this Mac guidance.

Local APFS roots offer a secondary Quick scan (experimental) action beside Scan all drives. The normal action always scans every folder. Quick scan first builds a baseline and then reuses unchanged Mac folders; other drives retain their usual scanning method. Hover guidance explains baseline creation. Scan history distinguishes quick scans from folder walks and displays the reason for full refreshes or unavailable caching. This remains a separate explicit action because asynchronous notifications can lag recent writes, and a full scan remains useful for fresh observations.
