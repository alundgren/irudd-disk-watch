# Native worker

Windows continues to use the existing direct `dw-scan.exe` scanner and deletion CLI. Its MFT reads, fallback, file-sharing guards, parallel deletion, process diagnostics and static CRT configuration are unchanged. Worker mode adds Windows account/root inspection and capacity, with scan and delete capabilities disabled there.

macOS and Linux use `dw-scan --worker`. See [the wire protocol](../docs/worker-protocol.md). The desktop keeps history; this executable observes and changes files only on its execution host. Mounted choices come from the native `volumes` operation, bounded to 1,024 rows and the protocol frame limit. Its result records observation time, truncation and total enumeration errors. Choices are advisory: selection must inspect the root and compare any captured mount/device identifiers. macOS uses cached mounts and native local volume names, recommending Data separately from the read-only System volume. Linux decodes mountinfo bytes, omits pseudo filesystems and known local file bind mounts, and keeps the root mount visible. Windows combines local volume mount paths and logical drives; mapped network metadata remains unknown until deliberate inspection. Enumeration does not traverse contents or query known network volumes.

Unix components retain canonical base64 bytes. Display labels escape backslashes and the UTF-8 bytes of Unicode control, format and line/paragraph separator characters. Invalid UTF-8 bytes use `\xNN`. The Unicode categories are pinned to version 16. The shared [label corpus](tests/unix-labels.json) is checked by the native tests. Typed macOS paths resolve case and Unicode normalization aliases to actual directory-entry bytes before becoming rules. Root directory records use the separate root observation instead of encoding `/` as a component.

Unix scanning holds directory descriptors and skips symlinks. It records regular files and directories, counts symlinks, mount boundaries and special files as intentional skips, retains total error counts with at most 500 samples, and folds small files into directory totals. Birth time comes from native creation metadata when available, otherwise null. The complete tree remains in memory before output, as in the Windows scanner. Linux uses metadata-only file descriptors; macOS uses descriptor-relative native filesystem attributes and stat data without opening regular files. Neither reads file contents. Linux requires `/proc/self/fdinfo` mount identifiers, including bind mount detection. macOS uses physical filesystem identifiers for mount checks. APFS volume-group logical identifiers can otherwise make System files look as if they belong to Data. The regular-file attribute query requests the physical filesystem ID while retaining stat device/inode observations, without opening file contents.

macOS scans use `getattrlistbulk` to read names, physical volume IDs, file IDs and object types in bounded batches. A fresh descriptor-relative `fstatat` checks the current mounted device, file ID and kind and supplies current sizes and timestamps. Directory opens, mount checks, exclusions and cleanup validation remain independent of the bulk records. One scratch buffer is reused between batches; recursive traversal retains only the pending entries in each directory's current batch. Unsupported bulk queries fall back to the original directory reader before yielding entries. Entries missing bulk identity attributes use the original per-file observation. Later read failures remain errors rather than restarting a directory and double-counting it. Both paths report the existing `walk` method and scan policy. APFS snapshots can report different physical bulk device numbers and mounted stat device numbers, so scope checks use stat's mounted device and the physical volume ID separately.

To compare workers without scanning personal files, preserve a baseline executable and run `python3 scripts/bench-macos-metadata.py /absolute/baseline/dw-scan scanner/target/release/dw-scan --output /absolute/results.json` from the repository root. It creates and removes owned fixtures, alternates baseline/candidate runs, compares all captured paths, identities, timestamps and totals, and reports warm-cache timing and native peak RSS. It does not establish cold-cache performance or live cloud-provider behavior.

The optional macOS `incremental: true` scan uses a per-volume FSEvents stream and a private baseline under `scan-cache-v1` in worker state. The stream starts before observation. Event paths use physical volume-relative components so Data firmlinks do not confuse scope checks. Changed folders and ancestors are read again; unchanged, error-free subtrees may be reused after their directory identity is checked. Subtrees containing hard links or future timestamps are always read again, and unavailable directories are retried. Lost events, unknown event flags, mount changes, replay timeout, invalid volume history, changed rules or grouping, and invalid cache data fall back to a full scan. Baselines expire after ten incremental runs or 24 hours. A busy tree that changes during reconciliation receives a full scan. Existing full scans have no event-stream or cache overhead.

The cache has an exclusive per-root writer lock, owner-only files, a checksum, bounded records and a 512 MiB size limit. Its flat directory records avoid JSON nesting limits on deep trees. Writes sync a temporary file and atomically replace the baseline; cancellation preserves the previous cache, and later writers remove abandoned temporary files. The persisted event checkpoint includes only events drained before observation, so events arriving during or after scanning remain eligible for replay. Cache format version changes must accompany changes to stored observation semantics. Cache data never approves deletion; cleanup retains its independent live checks.

FSEvents is advisory and notifications arrive asynchronously. A short collection interval handles observed startup delays, and the scanner reconciles delivered changes before emitting a reused tree. It cannot promise an atomic view while other processes write. Quick scans remain opt-in; the normal scan reads every folder. This follows [Apple's guidance on event history and periodic full scans](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/UsingtheFSEventsFramework/UsingtheFSEventsFramework.html). Run `python3 scanner/tests/macos_incremental.py scanner/target/release/dw-scan --output /absolute/results.json` for owned-fixture comparisons of complete trees, timestamps, identities, skip counts, permission recovery, aliases, cancellation and cache recovery. Increase `--folders` and `--files-per-folder` for timing measurements; these are warm-cache measurements, not whole-disk predictions.

Cleanup starts disabled and is available only on APFS and Linux mounts whose native mount table identifies ext4. Other filesystems remain scan-only. Linux mount IDs are matched to the filesystem type using the [kernel mountinfo format](https://docs.kernel.org/filesystems/proc.html#proc-pid-mountinfo-information-about-mounts); the ext-family magic alone cannot distinguish ext2/ext3. On macOS, opt-in requires an owner-controlled, writable directory without group or other write permission; elevated accounts and `/` cannot enable cleanup, every traversed directory must satisfy that policy, and directories with extended ACLs remain scan-only. On Linux, the root may be `/` and each folder is checked on its own: ancestors must belong to the account or root, targets and their contents to the account, with no unsticky group or other write access except through the account's private group, and no POSIX ACL entries for named users or groups. Linux refuses root and processes with effective capabilities. [The worker protocol](../docs/worker-protocol.md) lists the exact rules. The selected root and its immediate children remain ineligible. Saved target device, inode, mount and kind are required; a replacement observation never approves a saved target.

Cleanup supports cooperative writers and a quiescent tree. Stop writers before opting in or deleting. Descriptor-relative non-following traversal rechecks the root, mounts, ancestors and leaf identities before mutation, and stops subsequent work after a detected change or failure. Symlink leaves are unlinked without visiting their targets. A four-thread pool removes descendants without a count pass. Unix descriptors do not prevent another process from renaming an opened directory, and identity checking followed by unlink is not atomic. Concurrent hostile writers are outside this contract. Identifier reuse and changes after the final check remain possible.

The account-wide lock is an owner-only regular file under `/tmp`, keyed by effective UID and shared across state-directory profiles. The worker refuses unexpected ownership, permissions, file type, hard links or replacement. It never removes that lock file. Private profile state stores the installation ID, cleanup policies and deletion receipts across executable upgrades. A started receipt is synced before mutation, then updated and synced after selected-target results. An interrupted request may already have deleted files. Repeated operation IDs return status and never restart work; different payloads are refused. A crash can leave a running receipt, which becomes interrupted when its process lock is free. There is no exactly-once guarantee.

Receipt storage retains all IDs, including uncertain records. At 10,000 receipts new deletion operations are refused, rather than silently expiring replay protection. Receipt maintenance requires a deliberate operator decision; never discard running or uncertain records to make space. Large requests can also be refused before mutation when their worst-case receipt would exceed the 4 MiB frame limit.

Keep stdin open and send pings during operations. EOF, cancellation or 20 seconds without input stops work. A watchdog gives cleanup up to two seconds to persist interruption, then exits blocked workers with a nonzero status. If it terminates before the final receipt update, status retrieval reports interrupted work without replay. Blocking filesystem calls can delay cooperative cancellation until the watchdog terminates the process.

Run the headless checks with Rust and Python 3:

```sh
cargo test --manifest-path scanner/Cargo.toml --locked
cargo build --manifest-path scanner/Cargo.toml --release --locked
python3 scanner/tests/worker_smoke.py scanner/target/release/dw-scan
cargo check --manifest-path scanner/Cargo.toml --target x86_64-pc-windows-msvc --locked
```

Tests create and delete only their own private temporary fixtures. They exercise byte names, timestamps, unreadable-file observation and unlink, permission coverage, opt-in/depth restrictions, symlink sentinels, hard links, moved opened ancestors, a leaf swap immediately before the final check, root/mount mismatch, account-wide lock contention, receipt recovery and blocked-output liveness. Actual invalid-byte filenames require Linux; APFS can reject their creation. Privileged mount/unmount fixtures and installed-app filesystem permission behavior need separate isolated environments. Cross-target compilation does not establish the Windows release gate, elevated MFT behavior or same-machine performance.
